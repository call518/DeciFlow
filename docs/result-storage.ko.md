# 결과 저장

[English](result-storage.md) | [문서 안내](README.ko.md)

Task 결과·원본 입력·Action 결과·수동 정정·실행 집계는
`DECIFLOW_DATA_DIR/deciflow.sqlite3`에 Source·Criteria·Task·Action·SSH Host·일반
설정 및 SSH Key 메타데이터와 함께 저장합니다. 설정은 내부 ID를 키로 항목별 레코드로 저장하며 중첩 필드는
DB 안의 JSON 값으로 보존합니다. 별도 DB 서버나 환경변수는 필요 없습니다.

항목별 선택값·구간과 Choice 확실성은 결과를 저장할 때 `result_decisions`에 인덱싱합니다.
필터는 전체 실행을 대상으로 동작하며 매번 전체 결과를 다시 평가하지 않습니다.

## 제한된 결과 로딩

- Settings → Configurations의 Results per Page는 기본 **30건**이며 10·30·50·100건을 선택합니다.
- 서버에서 필터와 커서 페이지 조회를 적용합니다. 브라우저는 현재 페이지만 유지하고
  이전 페이지는 필요할 때 조회합니다.
- 최신 페이지는 마지막 수신 커서 이후 결과만 요청합니다. Main 이외 화면과 숨겨진
  탭에서는 조회를 멈추며 Task는 독립적으로 계속 실행합니다.
- 이전 페이지와 일시정지 목록은 새 결과가 와도 유지합니다. Latest Results로 최신
  페이지에 복귀합니다. 지표·차트는 페이지나 필터와 무관하게 실행 전체 기준입니다.
- 저장 시 집계를 증분 갱신합니다. 실행별 최근 이벤트 캐시는 최대 128건이며 완료된
  작업 객체는 32개를 초과하면 캐시에서 제거합니다. 저장된 Task 이력은 유지합니다.
  처리량은 실행 전체 성공 건수와 경과시간을 사용합니다. 정확한 Median·P95·P99는
  매번 원문 결과 전체를 읽는 대신 `processing_times`의 시간별 누적 건수를 사용합니다.
  실행별 서로 다른 처리 시간당 한 행을 저장하며 Task 삭제 시 해당 히스토그램도 삭제합니다.
- **Export All JSON**은 시작 시점 커서까지의 실행 전체 결과와 수동 정정을
  스트리밍하며 브라우저나 서버에 전체 결과를 올리지 않습니다.
- **Export Reviewed JSON**은 어떤 판단 항목이든 AI와 다른 수정값이 있는 성공 결과를
  조회합니다. 부분 인덱스와 제한 크기 배치를 사용하며 원래 결과 전체와
  `reviewerDecisions`를 보존하고 별도 저장소에 결과를
  중복 저장하지 않습니다. 화면 필터는 내보내기에 영향을 주지 않으며 비우거나 원래
  값과 같은 수정은 제외합니다.


누적 결과 건수에 비례해 결과 메모리를 늘리는 구조를 제거했습니다. 활성 호스트·파일,
개별 이벤트 크기·병렬도·SQLite 및 OS 캐시는 여전히 메모리를 사용합니다. 인덱스 페이지
조회는 과거 전체 결과를 순회하지 않지만 임의 부분 문자열 검색은 많은 행을 조회할 수
있습니다. 검색 입력은 지연 반영합니다. 디스크 사용량은 계속 늘며 자동 보존기한·정리는
없습니다. 모든 검색·입력 부하에서 CPU가 일정하다는 보장은 아닙니다.

## 실행 복구

`pending_work`에는 제한된 크기의 미완료 입력을, `source_checkpoints`에는 실제
소스별 읽기 위치를 저장합니다. 대기열 삽입과 위치 갱신, 결과 저장과 대기열 제거를
각각 하나의 트랜잭션으로 처리합니다. Action 실행 의도와 결과는 별도로 기록하여
불확실한 외부 효과를 자동으로 반복하지 않습니다. 고정된 Criteria·Action 정의는
실행 스냅샷에 포함합니다. 기존 SQLite 이력에 테이블을 자동 추가하므로 Reset은
필요 없습니다. 상태 복구·파일 검증·구버전 실행의 적용 경계는 [Tasks](tasks.ko.md#서버-재시작-후-복구)를 참고하세요.

## 초기 생성과 백업

새 데이터 경로에는 번들 Source·Criteria·Elasticsearch 샘플 Action과 기본 비활성 Task를 SQLite에 생성합니다.
저장한 빈 목록은 빈 상태를 유지합니다. 설정 JSON·run.json·events.ndjson은 생성하거나
이관하지 않습니다. 이전 JSON 설정과 구형 결과 DB는 가져오거나 자동 변환하지 않습니다.
기존 설치에 변경된 구조를 적용하기 전 개발 데이터를 Reset하세요. `profiles/`의 번들 Criteria
JSON은 읽기 전용 초기값으로 유지합니다.

로컬 파일시스템의 데이터 경로마다 DeciFlow 프로세스 하나를 사용합니다. SQLite는
WAL·FULL 동기 커밋·연결 캐시 2MiB를 사용합니다. 활성 DB는 공유 네트워크 파일시스템에
두지 마세요. 일관된 백업은 DeciFlow를 중지한 뒤 전체 데이터 경로를 복사하거나
SQLite 백업 API를 사용합니다. 실행 중 DB 파일 하나만 복사하면 WAL의 기록이 빠질 수
있습니다. 입력 데이터와 SSH 개인키가 포함되므로 백업도 보호해야 합니다.

## 향후 DB 확장

애플리케이션은 `ResultRepository` 인터페이스를 사용하고 `open_result_store()`가
구현체를 선택합니다. SQL·트랜잭션은 `SQLiteResultStore`에 분리했습니다.
PostgreSQL·MySQL 지원은 이 인터페이스 구현과 팩토리 확장, 이전·동시성 검증으로
추가할 수 있습니다. 설정 SQL은 `config_store.py`에 분리되어 있으며 이 저장소도 해당 DB 구현이 필요합니다. 현재 구현은 SQLite뿐이며 PostgreSQL·MySQL 접속 설정은 없습니다.

로컬 합성 데이터 5천 건과 5만 건을 비교했을 때 30건 조회 중앙값은 모두 약 0.37ms였습니다.
해당 환경의 인덱스 조회 측정이며 추론 전체·텍스트 검색·운영 성능 보장은 아닙니다.

Task 삭제 확인창에서 승인하면 Task 정의·실행 이력·결과·수동 정정을 영구 삭제합니다. 원본 Source 파일은 삭제하지 않습니다. SQLite의 삭제 공간은 이후 저장에 재사용하며 DB 파일 크기가 즉시 줄지는 않을 수 있습니다.

전체 초기화는 **Settings → Configurations → Reset DeciFlow**를 사용합니다.
확인 후 실행 중지·SQLite 종료·앱 데이터 전체 삭제·서버 재시작을 수행합니다.
[초기화 상세](configuration.ko.md#deciflow-초기화)를 참고하세요.


## 간결한 결과 저장

새 결과와 복구 대기열은 원문을 한 번 저장합니다. SQLite에서는 반복 Criteria·진단
질문 정의를 실행별 `result_contexts`에 내용 해시로 공유 저장합니다. 페이지 조회·
리뷰 검증·재생·내보내기 시 정의를 복원하며 캐시는 제한된 크기입니다. 독립적인
Action·내보내기 결과에는 정의를 포함하므로 내부 SQLite에 의존하지 않습니다.
`log_folded`는 대소문자 구분 없는 검색을 위한 의도적인 사본으로 유지합니다.
Task 삭제 시 공유 정의도 삭제합니다. 조회 시 저장 원본이나 ES 문서를 수정하지 않습니다.
현재 구조만 지원하며 이력을 자동으로 이전하지 않습니다.
